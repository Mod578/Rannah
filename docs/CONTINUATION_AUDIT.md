# تدقيق استكمال رنّة

التاريخ: 2026-07-16

## الحالة الموروثة

- كان مسار العمل المعطى فارغًا، بينما أثبتت `docs/DIRECTORY_AUDIT.md` أن جلسة Claude نقلت المشروع عمدًا من `~/Projects/Android` إلى `~/Projects/Bal`. أُعيدت نسخة المصدر إلى مساحة العمل مع إبقاء الأصل دون تعديل واستبعاد المخرجات المولّدة.
- لا يوجد مستودع Git أو تاريخ commits أصلًا؛ مجلد `.git` في مساحة العمل كان فارغًا. لذلك لا توجد تغييرات staged أو uncommitted قابلة للمقارنة، والمصدر والوثائق وتواريخ الملفات هي سجل الاستمرار المتاح.
- التطبيق مبني بـ Compose وRoom وHilt وAlarmManager، عربي وRTL افتراضيًا، ويحتوي الشاشات الرئيسية والمحرر والتفاصيل والسجل والإعدادات والأذونات والترحيب وودجت.
- خط الأساس المستعاد اجتاز `test` و`lint` و`assembleDebug` و`assembleRelease` في 2026-07-16. إصدار release الناتج غير موقّع للنشر، بينما debug موقّع بمفتاح Android المحلي ومناسب للتثبيت والاختبار.

## ما اكتمل سابقًا

- نموذج تذكيرات محلي دون حساب أو شبكة، وRoom كمصدر حقيقة.
- تكرار مرة واحدة/يومي/أسبوعي/ميلادي شهري مع اختبارات حدود الشهر.
- AlarmManager دقيق عند توفر الإذن، fallback غير دقيق، PendingIntent ثابت، إعادة جدولة بعد الإقلاع/التحديث/تغير الوقت والمنطقة، وWorkManager للمصالحة فقط.
- إكمال وتأجيل من الإشعار، سجل إنجاز، منع الحفظ المزدوج، وشاشات الأذونات.
- محلل عربي محلي يدعم الأرقام العربية والغربية وصيغ الأيام والأوقات النسبية والتكرار الأساسي مع معاينة قبل الحفظ.
- هوية «ليل ونهار» الهادئة، خط IBM Plex Sans Arabic، أيقونة وودجت، وثيم فاتح/داكن.
- عرض هجري بتقويم أم القرى مع ميلادي مقابل وتصحيح يدوي ±2 يوم.

## ما كان جزئيًا أو غير مكتمل

- وثيقة القرارات تقول إن Hijri مؤجل، رغم إضافة عرض هجري لاحقًا؛ لا توجد جدولة أو تكرارات هجرية في النموذج الحالي.
- عبارات مثل «أول رمضان» و«١٥ شعبان» لا يدعمها المحلل.
- تفضيلات التخصيص محدودة إلى الثيم، عرض التاريخ، تصحيح الهجري، ومدة التأجيل؛ لا يوجد اختيار نمط الأرقام أو كثافة العرض/الحركة.
- بيانات مطور وهمية وTODO ظاهرة في شاشة «عن التطبيق».
- ثلاثة استعمالات API مهجورة في Compose.
- لا توجد اختبارات واجهة/لقطات مرجعية. ADB لا يبدأ داخل sandbox بسبب منع socket/netlink، لذا يلزم تشغيله خارجه للتحقق المرئي.
- لا يوجد Git يمكن منه إعادة بناء branches أو commits، ولا AAB سابق.

## قرارات الاحتفاظ والتصحيح

- يُحتفظ بالمعمارية أحادية الوحدة وبحدود domain/parser/data/scheduling/ui؛ لا مبرر لإعادة كتابة.
- يبقى AlarmManager هو مسار التنبيهات الفعلية وWorkManager للمصالحة فقط.
- يبقى اتجاه الهوية «ليل ونهار» ونقطة جرس الرنّة؛ لا تُضاف زخارف تراثية متنافسة.
- يُستكمل Hijri كتقويم أم القرى محسوب مع تنبيه صريح أنه قد يختلف عن الإعلان، ولا يُسمى تاريخًا رسميًا مؤكدًا.

## خطة الإكمال

وسّع المستخدم النطاق في 2026-07-16 بمتطلبات جوهرية إلزامية موثقة في `REQUIREMENTS_COMPLETION.md`
(تجربة الإكمال والتأجيل، وضع المنبّه الحقيقي، اختيار نمط التنبيه، الجدولة الهجرية والميلادية كدلالة
حقيقية لا عرضًا فقط، إعادة تصميم المحرر، التخصيص المحلي، تدقيق UX، ومتطلبات التحقق). الخطة بعد التوسعة:

1. توسيع نموذج البيانات: حالة على مستوى «الحدوث» (مكتمل/متخطى/فائت) بدل حالة واحدة للتذكير،
   نمط التنبيه (تنبيه عادي / منبّه مهم)، نظام التقويم كجزء من الجدولة (هجري/ميلادي لمرة واحدة
   وشهري وسنوي)، مع ترحيل Room v1→v2 دون فقدان بيانات.
2. دلالات الإجراءات: تم / إيقاف / تأجيل / تخطي هذه المرة / إنهاء التكرار، بمعالجة idempotent
   للنوايا المكررة، وتراجع عن الإكمال الخاطئ، وتأكيد فقط للإجراءات المدمرة أو الشاملة للسلسلة.
3. وضع المنبّه الحقيقي: setAlarmClock، خدمة أمامية systemExempted تشغّل نغمة منبّه متكررة مع
   اهتزاز وتصعيد صوت اختياري ومهلة، شاشة منبّه كاملة فوق شاشة القفل مع إيقاف/تأجيل كبيرين،
   وfallback إشعار عالي الأولوية عند غياب إذن FSI، واستعادة بعد إعادة التشغيل وموت العملية.
4. إدخال هجري موثوق للمحرر (ولاحقًا المحلل) مع تكرار هجري شهري وسنوي واختبارات حدود 29/30
   والسنوات الكبيسة وتعديل ±2 المنعكس على الجدولة نفسها.
5. إعادة تصميم المحرر بالإفصاح التدريجي وملخص عربي صريح قبل الحفظ، واختيار نمط التنبيه بلغة
   طبيعية مع اقتراحات شفافة قابلة للعكس بحسب التصنيف.
6. تحديث الإشعارات والبطاقات والتفاصيل والقوائم والسجل: «تم» أساسية بأهداف لمس كبيرة، حالة
   الحدوث ظاهرة، تراجع، وتمييز واضح بين إيقاف صوت المنبّه وإكمال الالتزام.
7. إزالة المحتوى الوهمي والتحذيرات، وتحسين التخصيص والوصولية حيث تثبت الحاجة في التشغيل.
8. اختبارات JVM للدلالات الجديدة كلها، ثم تشغيل التطبيق على المحاكي إن توفر خارج بيئة sandbox
   وفحص الصوت وشاشة القفل وRTL والخط الكبير والفاتح/الداكن.
9. إعادة تشغيل جميع بوابات الجودة، تحديث تقرير الإكمال بالنموذج التفاعلي النهائي وقيود كل إصدار
   أندرويد، ونسخ APK debug الموقّع إلى `~/Downloads/rannah.apk` مع بياناته وSHA-256.

## نتيجة الاستكمال النهائية (2026-07-16)

- أُنجزت البنود الجوهرية 1–9 أعلاه. أضيفت دلالات الحدوث المستقلة، Alarm Mode، التقويم الحقيقي
  هجريًا وميلاديًا، المحرر الصريح، هرم الإجراءات والتأكيد/التراجع، واختبارات الجدولة ودورة الحياة.
- أضيف اختبار round-trip لكل جداول once/monthly/yearly الهجرية والميلادية وخيارات Alarm Mode،
  ثم اختبارات للبث القديم والمكرر وintent التأجيل المكرر؛ وبذلك أصبح مجموع JVM لكل build variant
  هو 125 اختبارًا (250 تنفيذًا عبر debug وrelease)، بلا فشل.
- نجح التسلسل الموحد `./gradlew test lint assembleDebug assembleRelease` في 4m21s. lint: صفر
  أخطاء و51 تحذير تحديث اعتماد فقط؛ أزيلت الموارد وتحذيرات Compose المحلية غير اللازمة، ولم تُعطل قاعدة.
- ثُبّت `app-debug.apk` وشُغّل cold launch فعليًا على AVD Android 15/API 35. فُحصت شاشة الترحيب
  والشاشة الرئيسية والمحرر العربي RTL، واختيار هجري/ميلادي، والثيم الداكن، ومقياس خط 150% دون crash.
- لم يوجد هاتف فعلي. لم يُثبت اختبار شاشة القفل/الشاشة المطفأة، سماع النغمة والاهتزاز، سلوك OEM
  والبطارية، أو تدفق أزرار الإشعار والمنبّه end-to-end؛ تغطيها مراجعة الكود وJVM لا تحقق جهاز فعلي.
- `release` المصغّر بُني بنجاح لكنه غير موقّع. نُسخ debug الموقّع والقابل للتثبيت إلى
  `/home/mod/Downloads/rannah.apk`، وثُبت نفس ناتج debug على المحاكي.
- لا يزال `.git` فارغًا، لذلك لا يوجد status/diff/staging/commits قابل للاستعادة أو التقرير عنه.
  لم تُحذف مصادر أو ملفات مستخدم، ولم يُنفذ reset/revert.

## تدقيق الجودة اللاحق (2026-07-16)

- أصبح AlarmManager intent يحمل occurrence المتوقع؛ أي بث متبقٍ بعد تعديل/إلغاء التذكير أو تسليم
  مكرر لا يستطيع إطلاق الموعد الجديد مبكرًا.
- أصبحت جدولة المتكرر بعد الرنين تبدأ strictly بعد الحدوث الذي رن، فتمنع إعادة تسجيل نفس الموعد
  عند التسليم المبكر بجزء صغير من الزمن.
- مُنع سباق START المكرر داخل AlarmRingerService بواسطة هوية occurrence وgeneration guard، ومُنع
  replay لنفس زر التأجيل مع بقاء التأجيل الحقيقي المتكرر بعد الرنين التالي.
- نجح `test lint assembleDebug assembleRelease` بعد الإصلاحات في 4m24s، وحُدّث APK المسلّم.
